# Loop 06：统一学习记忆、单一课程缓存与问答引导模式

## Goal

收敛互相重叠的全局教学偏好，删除 `cram` / `standard` / `top_score` 三档课程模式及其缓存选择逻辑，并让所有讲解统一读取一份经过验证的课程缓存。在模型问答中增加一个可切换的“引导模式”：开启后，系统先针对当前问题给出若干讲解方式或解题技巧选项，学生选择后再生成正式回答；关闭后维持直接问答。

## Requirements

- 全局教学偏好必须是可选的，并且只由用户主动修改；系统不得要求用户预先完成偏好设置才能学习。
- 完整删除 Quick Setup 流程及其五道问题、弹窗、完成度判断、重置入口、访客/登录恢复分支和浏览器 `tutorQuiz` 副本；新用户、老用户和访客都可直接进入学习区。
- 保留个人偏好修改入口和跨会话持久化，但将其缩减为一个可选的“长期要求”纯文本字段；留空时不向 Prompt 注入偏好。
- 删除 Markdown 档案编辑、Markdown 预览解析、AI 偏好草稿界面和 `/api/preference/draft` 接口。
- 模型问答可以读取用户手动保存的全局偏好，但不得读取 `inferredStyle` 或把单次引导选择写回全局偏好。
- 已登录用户的长期教学要求继续通过现有用户记忆存储持久化；访客的长期教学要求继续只在当前标签页保存，不把访客数据写入服务器。
- 对现有用户记忆执行一次性清理迁移，删除 `quiz`、`quizResetAt`、`preferenceProfile`、`inferredStyle`、`knownConcepts`、`weakConcepts` 和 `sessionSummaries`；迁移不得删除新的 `teachingInstructions` 或 `chat_sessions` 中的真实对话。
- 清理迁移必须同时覆盖 Neon `user_memory.data` JSONB 与本地用户 JSON 文件，并提供带时间戳备份、只读预览、影响数量报告和幂等执行；任一写入或校验失败都必须报错并停止，不能静默跳过。
- 浏览器端通过一次性存储版本迁移删除 `tutorQuiz` 和被取代的偏好副本；引导模式开关和访客真实会话不在清理范围内。
- 删除根据单次问答自动推断并长期写入 `inferredStyle` 的行为；教学风格只能由用户明确设置。
- 删除 `knownConcepts`、`weakConcepts` 和 `sessionSummaries` 的自动生成、合并、持久化、Prompt 注入和关键词重建；本 Loop 不再让模型根据一次问答猜测学生是否掌握某个知识点。
- 删除每次问答结束后用于推断学习标签的额外 Haiku 调用，并删除只为这些派生字段服务的 `/api/memory/rebuild` 能力。可靠的知识掌握度与薄弱点系统留到独立 Loop 重新设计。
- 保留原始会话和当前线程历史：已登录用户以服务端会话为持久化真源，浏览器只保存用于界面恢复的索引或临时状态；访客会话继续只保存在当前浏览器，不上传服务器。
- 修复已登录问答线程与服务端 `session_id` 的续接关系，保证同一线程后续轮次写入同一会话，而不是每轮生成新会话。
- 删除 `cram`、`standard`、`top_score` 三档课程模式：移除 `quiz.track` / 旧 `quiz.goal` 的运行时依赖、模式徽标、三档 Prompt、视觉文案分支、交互演示三档标签和旧缓存评分算法。
- 当前 162 份不带档位的新版课程缓存继续作为唯一正式缓存；对尚未具备新版统一缓存的 14 个课程目录，先从现有 `standard` 或旧名 `solid_b` 缓存中迁移一份通过格式校验的内容到统一缓存键。
- 全部课程确认可由统一缓存打开后，删除约 389 份不再参与运行的旧版模式/画像缓存文件，并删除对应回退选择逻辑。
- 老用户数据中的 `quiz.track`、`quiz.goal` 及其他旧档位字段随整个 `quiz` 对象由一次性迁移删除，运行代码不再保留旧档位兼容分支。
- 首页、课程问答栏和教材聚焦问答中的 `Fast` / `Balanced` / `Detailed` 只控制本次回答长短，不属于课程模式，必须保留。
- 首页问答和课程右侧问答栏都增加用户可控制的“引导模式”开关；两处共用同一开关状态和 `/api/ask` 问答链路。关闭时直接回答，开启时先展示针对当前问题的讲解方式或解题技巧选项。
- 两处的引导模式开关都放在各自输入框的工具栏中，与联网等问答工具并列；引导选项作为对话线程中的交互消息呈现，不使用顶部常驻横条或隐藏的更多菜单。
- 引导模式默认关闭，并记住用户上一次的开关选择。
- 引导模式开关仅保存在当前浏览器的本地存储中，首页与课程右侧问答栏共享；不写入账户记忆，也不跨设备同步。
- 引导模式开启后，由模型根据当前问题动态生成 2 至 3 个有实质差异的讲解方式或解题技巧选项，不使用固定通用菜单冒充个性化引导。
- 生成引导选项时检索整本教材，不把检索范围限制在当前小节；当前课程与小节只作为排序和理解问题的软上下文，不能排除其他章节的相关材料。
- 引导接口必须把实际检索到的教材证据与当前线程上下文提供给模型；教材没有命中时应明确记录“无教材命中”，不得伪造教材依据。
- 学生选中的讲解路径作用于当前主问题及其连续追问；发起新主问题或新会话时自动清除。
- 学生选中的讲解路径只存在于当前页面的问答线程状态中；关闭引导模式、退出问答或刷新页面也会清除。关闭后重新开启时，下一次提问重新生成选项。
- 引导选项不得自动变成长期全局偏好。
- 引导流程必须允许学生跳过并直接回答，不能形成无法退出的前置问卷。
- 引导选项生成失败、超时或返回无效结构时，必须在问答界面显示错误，不得静默回退。错误状态提供“重试生成选项”和“跳过引导，直接回答”，只有学生主动选择后才继续。
- 浏览器控制台和服务端日志记录可定位的完整错误；用户界面显示错误阶段与请求编号，但不得暴露密钥、内部堆栈或其他敏感信息。
- 引导选项通过独立的 `/api/ask-guidance` 接口生成；学生选择或跳过后，正式回答继续复用 `/api/ask`，避免把课程讲义生成或现有复杂问答逻辑混入引导阶段。
- 本 Loop 处理全局偏好、模型问答引导以及课程模式/缓存收敛；不修改课程讲义正文生成算法、GeoGebra、教材/OCR、Clerk 身份验证、Neon 表结构或 CSS 总体架构。

## Acceptance Criteria

- [ ] 用户可以主动编辑并跨会话保存一份全局教学偏好，也可以完全不设置。
- [ ] 新用户、老用户和访客进入学习区时均不再显示或依赖 Quick Setup；设置页也不再提供重做入口。
- [ ] 全局偏好只呈现为一个简短纯文本字段，不要求用户理解 Markdown，也不需要模型帮助改写。
- [ ] 模型问答 Prompt 只注入用户主动保存的全局偏好，不注入自动推断风格。
- [ ] 问答结束后不再额外调用模型生成 `knownConcepts`、`weakConcepts`、`sessionSummaries` 或 `inferredStyle`，Prompt 也不再注入这些派生字段。
- [ ] `/api/memory/rebuild` 及只服务于自动学习标签的前端入口、关键词重建和测试被删除；可靠掌握度系统不在本 Loop 内伪造替代品。
- [ ] 已登录用户同一问答线程的多轮消息写入并恢复自同一个服务端 `session_id`；访客会话只保存在当前浏览器。
- [ ] 原始会话与当前线程历史仍能正常保存和恢复，删除派生摘要不会删除真实对话内容。
- [ ] Quick Setup、用户记忆、课程界面和模型 Prompt 不再出现 `cram`、`standard`、`top_score` 课程档位。
- [ ] 所有有效课程章节只读取唯一统一缓存，不根据用户数据选择课程版本。
- [ ] 原本依赖旧回退的 14 个目录已迁移并通过课程打开与格式校验，迁移后旧模式缓存和评分回退代码均被删除。
- [ ] 迁移预览会报告受影响的 Neon 记录、本地用户文件和待删除字段，正式迁移可重复运行且第二次不会产生额外修改。
- [ ] 迁移完成后，用户记忆中不再保留 `quiz`、`quizResetAt`、`preferenceProfile`、`inferredStyle`、`knownConcepts`、`weakConcepts` 或 `sessionSummaries`。
- [ ] 迁移前备份可以恢复用户记忆；迁移失败会返回非零状态并停止，不会报告虚假的成功。
- [ ] 迁移不会删除 `teachingInstructions` 或任何 `chat_sessions` 真实消息，登录、问答和课程打开继续工作。
- [ ] `Fast` / `Balanced` / `Detailed` 回答长度选择在首页、课程问答栏和教材聚焦问答中继续工作。
- [ ] 单次请求“画图解释”或“分步骤解释”不会在未获用户确认时改变长期教学风格。
- [ ] 浏览器一次性迁移会删除 `tutorQuiz` 和被取代的偏好副本，但保留引导模式开关与访客真实会话。
- [ ] 引导模式关闭时，现有问答流程直接生成回答。
- [ ] 引导模式开启时，系统先返回可选择的讲解路径；选择或跳过后才进入正式回答。
- [ ] 首页问答和课程右侧问答栏的引导模式行为一致，并共享用户上一次保存的开关状态。
- [ ] 刷新或重新进入应用后，引导模式恢复用户上一次明确选择的开关状态；首次使用默认为关闭。
- [ ] 引导模式开关只在当前浏览器生效，不进入账户全局记忆或跨设备同步。
- [ ] 每次有效引导返回 2 至 3 个与当前问题直接相关且彼此有明显差异的选项。
- [ ] 引导检索覆盖整本教材；跨章节问题可以命中其他章节，当前小节只提高相关结果的优先级。
- [ ] 没有教材命中时不伪造引用，日志能区分“正常零命中”和“检索服务报错”。
- [ ] 连续追问沿用当前主问题已选路径；新主问题和新会话不继承旧路径。
- [ ] 引导生成失败时明确显示错误，保留原问题，并允许学生重试或主动跳过后生成普通回答。
- [ ] 引导错误可通过请求编号关联浏览器与服务端日志，用户界面不泄露内部敏感信息。
- [ ] 单次引导选择不会写入全局偏好。
- [ ] 删除被取代的状态、接口或模型调用后，登录、访客、偏好编辑和普通问答仍可工作。
- [ ] 新增针对旧数据兼容、问答 Prompt 偏好注入和引导触发边界的确定性测试。
- [ ] 课程讲义正文生成算法保持不变；只有课程档位和缓存选择逻辑被收敛。

## 已确认范围

- 用户选择第三档中的 A：优先收敛偏好系统。
- 用户确认移除 `inferredStyle` 自动偏好推断。
- 用户随后选择 A：删除 `knownConcepts`、`weakConcepts`、`sessionSummaries` 的自动推断、合并、Prompt 注入和关键词重建，也不再在每次问答后额外调用 Haiku；真实掌握度系统以后单独开 Loop。
- 用户明确要求保留“由个人主动修改”的全局偏好记忆，并确认本 Loop 完整删除 Quick Setup。
- 用户选择原始会话方案 A：登录用户以服务端会话为持久化真源，访客会话留在浏览器，并修复同一登录线程的 `session_id` 续接。
- 用户确认旧用户记忆不只在运行时忽略：先备份和预览，再直接清理 Neon JSONB、本地用户 JSON 与浏览器旧副本；清理必须幂等、失败中止，并保护真实会话。
- 用户要求把 brainstorming 的引导原则转化为模型问答中的可选开关，让学生选择当前问题的讲解方式及技巧。
- 用户确认引导模式默认关闭，并记住用户上一次的开关选择。
- 用户选择由模型为当前问题动态生成 3 个引导选项，接受开启模式时多一次模型调用。
- 用户确认选中的路径覆盖当前主问题及其追问，新主问题或新会话时清除。
- 用户确认引导模式同时覆盖首页问答与课程右侧问答栏。
- 用户选择界面方案 A：输入框工具栏开关 + 对话内引导选项。
- 用户确认引导模式开关只记在当前浏览器，选中的路径只保留于当前问答线程。
- 用户选择独立引导接口方案：先生成选项，再把选择传给现有正式问答接口。
- 用户选择教材检索方案 A：引导选项检索整本教材，当前小节只作为软上下文和排序信号。
- 用户选择整体落地方案 A：所有工作保留在当前功能分支和一个最终 PR 中，但按“删除旧偏好与档位逻辑、迁移统一缓存、统一真实会话、接入引导问答”四个阶段分别提交和验证。
- 用户选择把全局偏好缩减为简单文本框，并删除 AI 草稿能力。
- 用户决定删除 `cram` / `standard` / `top_score` 课程模式，所有讲解统一使用当前标准内容对应的唯一缓存。
- 用户确认保留问答的 `Fast` / `Balanced` / `Detailed` 回答长度选择。
- 用户确认迁移并验证统一缓存后，从 Git 删除剩余旧模式缓存文件。
- 用户确认完整删除 Quick Setup，而不是只删除其中的课程档位问题。
- 本任务是复杂任务，实施前需要中文 `design.md` 和 `implement.md`。
