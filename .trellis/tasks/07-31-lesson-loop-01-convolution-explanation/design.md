# 技术与教学设计

## 1. 设计结论

本 Loop 采用已确认的“三层桥接”路线：先用生活直觉回答 Why，再立刻对回公式回答 What，用第二个比喻解释图上动作回答 How，最后回到教材 Figure 2.7 进行严格验证。比喻不配图；全节唯一主视觉是一个连续 GeoGebra 场景。

课程不是把旧缓存补长，而是重新组织 `2.4-2` 的讲解顺序。课程缓存继续使用现有数据协议和 GeoGebra renderer，不新增模块。代码改动只修正 Figure 2.7 场景与外壳中的教材幅值错误，并补充相应测试。

## 2. 方案取舍

### 方案 A：教材先行

先展示 Figure 2.7，再推导翻转、平移和积分，最后补比喻。该方案贴书最紧，但学生在没有直觉时会先撞上 `t` 与 `τ`，不采用。

### 方案 B：比喻先行到底

先完整讲完墨水池和洒水车，再统一翻译成数学。该方案容易听懂，但学生可能记住故事却没有及时建立符号对应，不采用。

### 方案 C：三层桥接

每个抽象结论后立即给口语比喻，再立即映射回数学；步骤总结后用 GeoGebra 对照教材数值。该方案同时满足“听懂、会做、知道书上在哪”，被采用。

## 4. 固定教学原话与语义

### 4.1 Why：系统记忆

核心抽象句：

> 一个有记忆的系统，不会在输入结束后立刻把它忘掉。输入信号在每个历史时刻送进去的一小部分，都会留下一个缩放并延迟的系统响应；把这些响应全部加起来，才是现在看到的输出。

紧接墨水池比喻：

> 想象一个透明水池。你不是一次性倒进一桶墨水，而是在不同时间一滴一滴地往里滴。每一滴刚落下时颜色最浓，过得越久，就扩散得越开、变得越淡。现在整池水呈现的颜色，不是由最后一滴单独决定的，而是过去所有墨水滴到现在还剩下的颜色叠在一起。卷积逐滴算它现在还剩多少影响，再把所有影响加起来。

符号映射必须紧随其后：

```text
x(τ)             τ 时刻滴入多少墨水
g(t-τ)           经过 t-τ 后还剩多少影响
x(τ)g(t-τ)       这一滴对现在的贡献
积分              所有历史贡献连续相加
```

### 4.2 What：谁固定，谁扫描

先给出卷积积分，再用一句日历类比说明变量角色：算一个 `c(t)` 时，“今天” `t` 钉住不动，`τ` 像手指一样沿历史日期扫描。该类比只用于变量角色，不扩展成第三个完整故事。

### 4.3 How：图解动作

核心抽象句：

> 翻转和平移不是人为规定的怪动作，而是 `t-τ` 在图上的样子；逐点相乘是在算每个位置的局部贡献；积分是在算所有位置的总贡献。

紧接洒水车比喻：

> 把 `x(τ)` 想成沿 `τ` 轴铺开的农田，每个位置的庄稼密度不同；把 `g` 想成洒水车的喷水分布。先让洒水车掉头，这就是翻转；再让它沿农田开到位置 `t`，这就是平移。每个位置真正起作用的水量，等于当地庄稼密度乘以当地喷水量。把整片田的贡献全部加起来，就是这个停车位置对应的 `c(t)`。

必须保留“稀疏庄稼遇到大水”和“茂密庄稼遇到小水”两句对照，用来解释为什么需要逐点相乘，而不能只看重叠宽度。

## 5. GeoGebra 作为唯一主视觉

课程不再在 Demo 前展示 `![Figure 2.7]`。现有 `convolution_figure_2_7` 场景继续作为唯一 Applet，四个软引导状态保持不变：

1. `signals`：读取 `x(τ)` 与 `g(τ)`；
2. `flip`：显示 `g(-τ)`；
3. `slide`：拖动 `t`，观察 `g(t-τ)` 与移动支撑边界；
4. `integrate`：显示乘积区域、面积、完整 `c(t)` 曲线和当前输出点。

课程五步清单中的“记录扫描”并入 Demo 第四状态：当 `t` 改变时，当前面积同步成为输出曲线上的点。切换步骤保持当前 `t`，只有 Reset 恢复 `t=-4`。

GeoGebra 外壳、CDN 懒加载、scene registry、teardown、原生 range 控件和软引导协议均不重构。正常路径只显示活图；现有失败降级仍保留，以保证断网时课程可读。

## 6. 教材数学对齐

原 PDF Figure 2.7 的指数在 `t=-2` 处高度为 `2`。现有缓存和场景遗漏了系数 `2`，属于教材对齐错误。本 Loop 统一修正为：

```text
x(τ)        = u(τ+1)
g(τ)        = 2 exp[-(τ+2)] u(τ+2)
g(-τ)       = 2 exp(τ-2) u(2-τ)
g(t-τ)      = 2 exp(τ-t-2) u(t+2-τ)

重叠条件：  τ >= -1 且 τ <= t+2
首次接触：  t+2 = -1 -> t = -3

c(t) = 0                              , t <= -3
c(t) = 2[1-exp(-(t+3))]               , t > -3
```

关键数值：

```text
c(-4) = 0
c(-3) = 0
c(-2) = 2(1-e^-1)
c( 0) = 2(1-e^-3)
```

需要同步修改的现有所有权点：

- `app/interactive-demos/geogebra-convolution-figure-2-7.js`：信号、乘积、面积、输出公式及下图区纵轴；
- `app/interactive-demos/geogebra-demo.js`：失败降级公式和数值文案；
- `workspace/materials/lesson-cache/2_4-2/...en.md`：教材输入、推导、检查值和结论；
- Figure 2.7 定向测试中的预期值。

不修改或替换教材裁图与 OCR。当前裁图不再出现在正常课程流中，但仍属于受保护材料。

## 7. 与本书的连接

课程结束不列泛化行业名词，而是回答“为什么本书在这里教它”：

1. 第 2.4 节已经把 LTIC 零状态响应写成 `y(t)=x(t)*h(t)`；卷积是已知输入和冲激响应后求输出的方法。
2. 前面的 Example 2.9 用该关系求 RLC 电路回路电流，说明它可替代对每个新输入重新求微分方程。
3. 教材在 2.4-2 开头明确指出图解卷积有助于采样、滤波和只有图形描述的信号。
4. 下一小节 2.4-3 用 `h_1*h_2` 求级联系统的总冲激响应。

结尾固定收束为：卷积不是为了把两条曲线折腾来折腾去，而是在问，系统过去收到的每一小份输入，到现在还留下多少；全部加起来，输出是什么。

## 8. 失败、兼容与回滚

- 课程缓存保持现有 KC block 和 `data-demo-b64` 协议，不更改 dispatcher。
- 若 GeoGebra CDN 失败，课程正文、五步总结和教材用途仍然可读；失败公式同步为幅值 `2`。
- 幅值修正只影响 `convolution_figure_2_7`，不改变其他 GeoGebra 或 Canvas Demo。
- 分支可通过回滚课程缓存、该场景公式和定向测试独立撤销；不得回滚用户其他分支。

1. 静态检查课程只含一个 Figure 2.7 GeoGebra block，不含墨水/洒水图片和正常流静态教材图。
2. 数学定向测试从场景 API 验证 `t=-4,-3,-2,0` 的面积与输出，并检查幅值 `2`。
3. 生命周期测试继续验证步骤切换不重建、`t` 保留、reset 与 teardown 幂等。
4. 通过真实 `/api/section` 确认应用命中目标缓存，并检查编号 H2 能正确分页。
5. 运行 `npm run check` 与现有 GeoGebra、课程打开、CSS/视觉相关回归；本 Loop 不改 CSS 时只执行相关无回归检查，不制造样式元数据更新。
6. 在桌面与移动视口打开真实 `2.4-2`，检查文字、公式、GeoGebra 非空、曲线不裁切、控件不重叠且控制台无新增错误。
7. 在 `verification.md` 写中文完整验收和英文简短验收摘要，记录命令、关键数学值、截图结论与剩余风险。
