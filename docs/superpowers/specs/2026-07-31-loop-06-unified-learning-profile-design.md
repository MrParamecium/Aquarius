# Loop 06：统一教学要求、课程缓存、真实会话与问答引导

## 背景与决策

项目当前同时存在 Quick Setup、Markdown 偏好档案、AI 偏好草稿、自动推断风格、自动学习标签和三档课程模式。它们分别修改用户记忆、模型 Prompt、课程缓存选择和页面文案，但缺少可靠的学习效果证据，维护成本与行为不确定性已经高于收益。

本 Loop 采用完整收敛方案，而不是隐藏旧入口或继续兼容旧数据：

- 长期个性化只保留用户主动填写的一段教学要求；
- 真实会话只记录实际问题和实际回答；
- 每个有效课程小节只读取一份统一课程缓存；
- 引导模式只影响当前问题及其连续追问；
- 自动掌握度系统本 Loop 不做简化替代，以后单独设计。

所有工作位于 `codex/loop-06-tier-3-simplification` 分支，按四个可独立验证的阶段提交，最终合并为一个 PR。

## 最终模块边界

```text
用户主动填写的长期教学要求
                |
                v
用户提问 -> 问答引导（可选） -> /api/ask -> 真实会话
                |                 |
                v                 v
          整本教材检索       单次回答长度

课程页面 -> 唯一课程缓存
```

四块数据不得互相代替：

1. 长期教学要求回答“以后通常怎么讲”。
2. 真实会话回答“用户和系统实际聊过什么”。
3. 课程缓存提供经过准备和验证的课程正文。
4. 引导选择回答“这一个问题从哪条路径讲”。

`Fast`、`Balanced`、`Detailed` 只控制单次回答长度，不属于课程档位，继续保留。

## 范围

本 Loop 包含：

- 完整删除五步 Quick Setup；
- 收敛全局教学要求；
- 删除自动风格和学习标签；
- 清理旧用户记忆数据；
- 删除 `cram`、`standard`、`top_score` 课程模式；
- 迁移统一课程缓存并删除旧缓存；
- 修复登录用户真实会话的 `session_id` 续接；
- 为首页问答和课程右侧问答增加可选引导模式；
- 增加相应的确定性测试、接口测试和浏览器验证。

本 Loop 不包含：

- 新的知识掌握度、薄弱点或学习评价算法；
- 修改课程讲义正文的生成算法；
- 修改教材、OCR、章节映射或公式目录；
- 更换 RAGFlow、Neon 或 Clerk；
- 修改 Neon 表结构或认证协议；
- 修改 GeoGebra、课程测验或 CSS 总体架构；
- 将访客会话自动合并到登录账户。

## 第一阶段：删除旧偏好与课程档位

### 长期教学要求

用户记忆的新有效形态只保留以下与本功能有关的字段：

```json
{
  "teachingInstructions": "公式推导要完整，先讲直觉再讲计算"
}
```

`teachingInstructions` 必须满足：

- 类型为字符串；
- 保存前去掉首尾空白；
- 最长 1000 个字符；
- 空字符串表示清除；
- 留空时不向模型 Prompt 注入任何教学偏好；
- 服务端拒绝错误类型和超长内容，不做隐式截断。

偏好页面保留一个普通多行文本框、保存状态和清除操作。删除 Markdown 编辑与预览、默认档案模板、AI 草稿区、`/api/preference/draft` 以及与 Quick Setup 的联动。访客只保存在当前浏览器，登录用户通过现有用户记忆后端持久化。

Prompt 构建函数只读取 `teachingInstructions`。用户输入以单独、清楚标记的教学要求区段注入，不能与系统安全规则混合。该要求只进入正式 `/api/ask` 回答，不进入 `/api/ask-guidance`，从而保持引导选项本身具有差异。旧字段即使在迁移前短暂存在，也不能继续影响 Prompt。

### 删除自动学习标签

删除以下完整链路：

- 每轮问答后的 `anthropic/claude-haiku-4.5` 额外调用；
- `knownConcepts`、`weakConcepts`、`inferredStyle` 和 `sessionSummaries` 的生成与合并；
- `deriveMemoryFromSessions` 的关键词猜测；
- `/api/memory/rebuild`；
- 删除会话后重建学习记忆的前端调用；
- 上述字段的 Prompt 注入、接口补丁逻辑、日志和专属测试。

删除这些字段后不建立占位版掌握度算法。原始消息历史不是“已掌握”证据，不能重新包装为学习标签。

### 删除 Quick Setup

删除五道题、弹窗、完成度判断、首次进入阻塞、重做入口、恢复分支、`tutorQuiz` 浏览器副本和相关测试。新用户、老用户与访客均直接进入学习区。

Quick Setup 中的数学基础、时间压力、学习偏好、当前目标和课程档位都不再自动注入 Prompt。用户确实需要的长期要求由其自行写入文本框。

### 删除三档课程模式

删除 `cram`、`standard`、`top_score` 的运行时含义，包括：

- `quiz.track` 和旧 `quiz.goal` 依赖；
- 三档课程 Prompt 与模式徽标；
- 课程视觉和文案分支；
- 交互演示中的三档标签与选择；
- 旧缓存评分与画像匹配；
- DOM、CSS、夹具、测试和说明中的运行时引用。

历史设计文档可以保留这些名称作为演变记录，不视为运行时残留。

## 用户记忆清理

### 删除范围

一次性迁移直接删除：

```text
quiz
quizResetAt
preferenceProfile
inferredStyle
knownConcepts
weakConcepts
sessionSummaries
```

迁移保留 `teachingInstructions`、用户标识和必要时间字段。`chat_sessions` 是独立真实会话表或独立本地文件目录，不在删除范围内。

旧 `preferenceProfile.markdown` 不自动转换成 `teachingInstructions`。该内容可能来自 Quick Setup、默认模板或 AI 草稿，自动复制会把本次要删除的噪声重新带回新系统。迁移后长期教学要求默认留空，用户可重新主动填写。

### 迁移工具契约

迁移工具提供两个互斥模式：

```text
--dry-run   只读取并报告，不写数据
--apply     备份、清理、校验并输出结果
```

`--apply` 必须要求显式指定备份目录。备份包含带时间戳的 Neon 用户记忆 NDJSON 和本地用户 JSON 副本，不进入 Git，也不参与应用运行。

Neon 数据位于 `user_memory.data` JSONB。正式清理必须在事务中完成：读取与备份成功后更新，逐项校验受影响记录，再提交；任一步失败都回滚并返回非零退出码。本地 JSON 使用临时文件加原子替换，任一文件失败即报告具体路径并停止。

迁移是幂等的：第二次执行报告零个待删除字段，不能继续改写无关内容。迁移工具不在应用启动或普通请求中自动运行，避免部署时发生不可见的数据破坏。

浏览器使用一次性存储版本迁移删除 `tutorQuiz` 和被取代的偏好副本。该迁移保留引导模式开关和访客真实会话。

## 第二阶段：统一课程缓存

### 唯一缓存约束

课程运行时只接受当前 `LESSON_CACHE_VERSION` 对应的统一缓存键。缓存选择不再接收用户记忆，也不再调用 `normalizeQuizProfile`。缺失或格式非法时返回现有明确的课程未准备错误，不能扫描旧文件寻找“最接近”的版本。

教材来源仍用于教材页、OCR 和问答检索，不重新解释为用户课程档位。本 Loop 不修改教材文件与章节映射。

### 迁移顺序

当前有 162 份新版统一缓存，另有 14 个目录依赖旧内容。迁移清单必须按规范课程目录集合生成，而不是只比较文件总数：

1. 13 个目录选择明确的 `standard` 内容；
2. `lesson-cache/1` 选择早期标准内容 `solid_b`；
3. 将源内容写入当前统一缓存键；
4. 对每份内容执行现有标准化和格式校验；
5. 对规范课程目录集合执行完整命中检查；
6. 实际打开全部课程小节；
7. 全部通过后才删除约 389 份旧模式或画像缓存；
8. 最后删除旧回退读取器、评分函数和相关依赖。

任何小节缺失、源文件歧义或格式失败都中止删除阶段。迁移报告记录小节、源文件、目标文件、校验结果和失败原因，便于审查。

## 第三阶段：统一真实会话

### 真源规则

已登录用户以服务端会话为持久化真源。浏览器只保存当前界面恢复所需的会话编号和临时渲染状态，不维护第二份可独立覆盖服务端的完整真源。访客会话继续留在浏览器，不上传服务器，也不在登录时自动合并。

首页线程与课程问答线程各自持有当前 `session_id`。首次正式回答成功后，前端接收服务端返回的编号并立即绑定；后续轮次、连续追问和恢复后的新消息必须回传同一编号。首页会话的 `origin` 为 `main`，课程问答会话的 `origin` 为 `learn`。

### 服务端契约

`persistSessionTurn` 从“编号或空值”改为可区分结果的明确契约：

- 未提供编号：创建新会话；
- 提供且属于当前用户：追加到该会话；
- 编号格式非法、不存在或不属于当前用户：返回明确失败，不新建替代会话；
- 存储写入失败：返回明确失败，不声称已保存。

跨用户与不存在的会话对外统一返回未找到，避免泄露其他用户是否拥有该编号。认证身份只来自已验证 Bearer Token，客户端 `uid` 不能选择读写对象。

`/api/ask` 只有在问答内容和会话写入都成功后才返回成功及 `session_id`。写入失败返回请求编号和明确错误，浏览器保留用户原问题用于重试，不能静默显示“已完成”。

删除会话只删除真实会话，不再调用模型或关键词规则重建用户记忆。

## 第四阶段：问答引导模式

### 前端状态

首页问答与课程右侧问答在输入框工具栏中各显示同一个引导模式开关。开关默认关闭，使用同一个浏览器本地键保存，刷新后恢复但不跨设备同步。

引导线程状态包含：

```text
关闭
等待提问
检索并生成选项
等待选择
正式回答
完成
失败
```

同一时刻只允许一个有效引导请求。新请求会中止旧请求；取消操作终止当前请求并保留输入。引导选项以对话内交互消息呈现，不使用顶部横条或隐藏菜单。

选中的路径显示为可清除的当前状态。它用于当前主问题及其连续追问；首页发起新的主问题、课程切换小节、创建或恢复其他会话、关闭引导、刷新页面或用户主动清除时失效。引导选项和选择不写入用户记忆，也不写入永久会话；永久会话只保存最终真实问题和回答。

现有轻量意图判断保留在引导之前。问候、致谢等非课程问题继续直接得到简短响应，不为“谢谢”生成三种讲解路径。

### 引导接口

新增 `POST /api/ask-guidance`，认证要求与 `/api/ask` 相同。请求包含：

```json
{
  "prompt": "为什么卷积需要翻转？",
  "history": [],
  "sectionId": "2.4-2",
  "sectionTitle": "Convolution",
  "lessonContext": "当前课程上下文",
  "bookSource": "new",
  "language": "zh"
}
```

服务端为每个请求生成不可预测的 `request_id`。成功响应包含 2 至 3 个有效选项以及教材检索状态：

```json
{
  "request_id": "...",
  "options": [
    {
      "id": "visual_overlap",
      "title": "从滑动重叠的直觉讲",
      "description": "用图像和面积变化理解翻转的作用",
      "instruction": "先解释翻转，再逐步展示平移和重叠"
    }
  ],
  "retrieval": {
    "status": "hit",
    "count": 4
  }
}
```

选项必须与当前问题直接相关、彼此有实质差异、可以直接指导正式回答。少于 2 个有效选项、重复选项、非法 JSON 或字段超限均视为生成失败。

学生选择后，前端将经长度和结构限制的选项指令传给 `/api/ask`。正式问答继续使用原有回答长度、附件、联网开关、教材证据与历史链路；引导只增加本次讲解路径，不覆盖系统规则或长期教学要求。点击跳过时不发送引导指令。

### 整本教材检索

引导检索覆盖当前教材的完整检索集合，不限制在当前小节。问题文本是主查询，当前小节、课程正文和线程历史只是软上下文与排序信号，不能排除其他章节结果。

引导复用现有 RAGFlow 与本地 OCR 能力，但每次请求只选择当前已配置的检索后端。已配置后端发生技术错误时必须进入失败状态，不能在日志里警告后悄悄切换；未配置 RAGFlow 的本地开发环境可以明确选择本地 OCR 后端。

正常完成但零命中不是技术错误。此时响应标记 `retrieval.status = "empty"`，模型可根据问题与线程上下文生成讲解路径，但不能声称来自教材或制造教材引用。

### 异常处理

技术错误响应包含：

```json
{
  "error": "教材检索失败",
  "stage": "retrieval",
  "request_id": "..."
}
```

`stage` 只使用 `retrieval`、`generation`、`validation` 或 `persistence`。界面显示用户可理解的阶段、请求编号、“重试生成选项”和“跳过引导，直接回答”。用户未明确点击前不自动进入普通回答。

浏览器控制台和服务端日志使用相同请求编号记录完整错误。界面和响应不得暴露密钥、内部 Prompt、堆栈、数据库连接或其他敏感信息。

## 验证

### 用户记忆与迁移

1. 新用户、旧用户和访客均可直接进入学习区。
2. 教学要求能保存、读取和清除，空值不注入 Prompt。
3. 错误类型和超长教学要求被拒绝。
4. 迁移预览不写数据并准确报告影响数量。
5. 正式迁移删除全部七类旧字段，保留教学要求和真实会话。
6. 第二次迁移为零修改。
7. 备份恢复测试能还原迁移前用户记忆。
8. 任一 Neon、本地文件或校验失败均返回非零状态。

### 课程缓存

1. 规范课程目录集合与统一缓存目录集合完全相等。
2. 14 份迁移内容全部通过格式校验。
3. 每个小节实际打开成功。
4. 缓存缺失明确失败，不调用旧回退。
5. 运行代码不再引用三档课程模式和旧评分函数。

### 真实会话

1. 登录用户连续两轮只创建一个服务端会话。
2. 恢复会话后下一轮继续追加到同一编号。
3. 首页与课程会话记录正确来源和小节信息。
4. 非法、不存在和跨用户编号不会创建替代会话。
5. 存储失败在界面与日志中可见。
6. 删除会话不触发模型调用或记忆重建。
7. 访客真实会话不写入 Neon。

### 引导问答

1. 开关关闭时不调用 `/api/ask-guidance`。
2. 两处开关共享浏览器状态，首次使用默认关闭。
3. 开启后严格先返回 2 至 3 个有效选项，再由用户决定是否正式回答。
4. 整本教材检索可以命中当前小节之外的章节。
5. 正常零命中与检索服务错误得到不同状态。
6. 超时、非法 JSON、重复选项和字段超限进入明确失败卡。
7. 重试、跳过、取消和清除行为符合状态机。
8. 连续追问沿用选择，新主问题、新会话、切换小节和刷新不沿用。
9. 引导选择不进入全局教学要求或永久会话。
10. `Fast`、`Balanced`、`Detailed` 与联网开关继续独立工作。

### 完整回归

运行项目现有检查、认证测试、会话测试、课程缓存测试、Smoke、CSS Probe 和视觉回归。使用桌面与手机视口实际验证首页问答、课程右侧问答、偏好页面、Recent 会话和课程打开，不允许控件重叠、文字溢出或动态状态导致布局跳动。

最后精确扫描运行代码，确认不存在 Quick Setup、`/api/preference/draft`、`/api/memory/rebuild`、自动学习标签、三档课程模式或旧缓存评分与回退。历史设计文档中的说明不计入运行时残留。

## 发布与回滚

代码与缓存修改通过四个独立提交回滚。用户记忆清理不随应用启动自动执行；部署新代码并完成健康检查后，先运行 `--dry-run`，审核备份和影响报告，再显式运行 `--apply`。

若代码验证失败，回滚对应提交。若用户记忆迁移验证失败，事务回滚；若迁移提交后发现问题，使用同批次备份恢复。删除旧缓存前保留 Git 提交点，统一缓存未完整验证时不得进入删除步骤。

本 Loop 的成功标准不是隐藏几个入口，而是让运行时只剩一份主动教学要求、一套真实会话、一份课程缓存和一个明确可退出的问答引导流程。
